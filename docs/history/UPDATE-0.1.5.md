# 0.1.5: 스트라타젬의 상위 항목 소유권 연결

사용자의 0.1.4 로그에서 소유권 코드 검색은 성공했습니다.
검색 주소는 `0x136F910`, 전역 데이터는 `0x347CEF8`이며 별도 코드의 레이아웃과 일치했습니다.
실패 단계는 이후 후보 생성입니다. 선택 목록 91개가 모두 직접 상태 1이라 제외됐습니다.
`0xB4` 필드도 0인 항목 32개, 1인 항목 59개였습니다. 이 숫자만으로 소유 여부를 단정하지 않았습니다.

## 근거와 수정

같은 game.dll SHA-256 `2e2c3b7c2500646dadd5f2b4c6e0504dbb7e7896139f64cddc0d1813c718f51e`를
명시한 HD2Runtime의 스트라타젬 분석은 네이티브 가용성 함수 `0x136FC20`의 규칙을 설명합니다.
선택 항목 자체 **또는 연결된 상위 항목**의 정의 상태가 2/4이면 소유한 항목입니다.
기존 구현은 의상용 직접 상태 검사만 사용해 상위 항목 연결을 누락했습니다.

- 선택 행 `+0x10`의 back 값을 읽고 `행 주소 - back × 24`로 직접 연결된 부모 행만 확인합니다.
- 같은 관찰 테이블 안의 이전 행인지, 상태 인덱스가 범위 안인지 확인합니다. 임의 체인 탐색은 하지 않습니다.
- 실제 소유 상태는 계속 2/4여야 합니다. 상태 1이나 선택 목록에 존재한다는 사실만으로 허용하지 않습니다.
- 선택 항목·offer·부모 연결·부모 행·소유 상태·테이블 루트를 증거로 묶어 적용 직전에 재확인합니다.
- 스트라타젬에는 의상용 `+0xB4` 검사를 적용하지 않습니다. 참고 분석의 네이티브 조건인
  StratagemInfo `+0xC0` bit 0(enabled), `+0x80` bit 1(selectable)과 기존 임무 목록 조건을 적용합니다.
- 관련 네이티브 명령 5곳의 공개 바이트를 추가 확인합니다. 불일치 시 거부합니다.
- 사용자 로그의 포커스 없음 값 `0xFFFFFFFF`에서는 알려진 네이티브 setter로 첫 슬롯에 초점을 맞춥니다.
  확인되지 않은 값으로 복원하지 않고 첫 슬롯 초점을 유지합니다.

소유권·해금 값을 쓰거나 선택 제한을 제거하지 않았습니다. 새 메모리 쓰기 경로도 추가하지 않았습니다.
선택·저장 호출은 기존 경로를 유지하며 실제 적용 성공은 아직 미확인입니다.

## 설치 및 남은 범위

`dist/RLMmods-0.1.5-private-untested.zip`을 사용합니다. 게임을 닫고 기존 RLMmods를
모두 비활성화한 뒤 새 ZIP을 배포하세요. Bingus 선택적 공존, 다른 boot.lua 교체 모드와의 충돌은 동일합니다.
제거는 같은 매니저에서 비활성화 후 Purge/Deploy합니다. 자동 설치나 원본 변경은 하지 않습니다.

세로 버튼 UI는 유지합니다. 저장·불러오기는 비활성 예약 버튼이고 전체 장비 랜덤화는 미완성입니다.
이번 버전도 컴파일·패키징만 수행하며 게임 실행, 테스트, 설치 및 플레이 검증은 수행하지 않습니다.
소스 ZIP은 만들지 않으며 원본 boot를 포함한 설치 패치는 공개하지 않습니다.
