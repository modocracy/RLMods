# 0.1.4: 소유권 코드 위치 조회와 세로 버튼 UI

## 사용자 로그로 확인한 실패 지점

0.1.3 세션에서 기본 스트라타젬 목록은 91행, 선택 가능 표시도 91개로 읽혔습니다.
그러나 `Unsupported game code: progression_owned_layout`로 소유권 관찰기가
시작부터 비활성화됐습니다. 이 때문에 선택 적용 단계에는 도달하지 못했습니다.
별도로 게임이 반환한 기존 그리드 포커스 값 4도 RLMmods의 `<4` 검사에 걸렸습니다.
이는 사용자 실행 로그 분석입니다. 개발자가 게임을 실행하거나 테스트하지 않았습니다.

## 수정

이전에는 참고 소스의 RIP 변위와 알려진 전역 주소로 추정한 함수 주소를 고정했습니다.
이제 주소를 추정하지 않고 참고 소스의 전체 150바이트 명령 패턴을 검색합니다.
소스의 원래 마스크가 지정한 오프셋 99..102의 RIP 변위 4바이트만 가변 처리합니다.
나머지 명령과 구조 오프셋은 모두 일치해야 합니다.

- 지원 이미지 타임스탬프는 그대로 제한합니다. 검색은 현재 프로세스의 game.dll 실행 섹션에서만 수행합니다.
- 64 KiB 단위, 최대 총 128 MiB로 제한하며 패턴이 정확히 한 곳에 있어야 합니다.
  읽기 실패나 복수 일치, 미발견 시 중단합니다.
- 실제 명령에서 읽은 전역 대상 주소가 별도로 일치한 스트라타젬 조회 코드 두 곳과
  같아야 하고, 항목 테이블과 개수 필드 위치도 같아야 합니다.
- 일치한 실제 바이트 전체를 보존해 소유권 관찰마다 변경 여부를 확인합니다.
  소유·해금 상태나 선택 제한을 수정하지 않습니다.
- 사용자 로그에서 관찰된 기존 포커스 4는 보존·복원하도록 허용합니다.
  선택 대상으로 사용하는 스트라타젬 슬롯은 여전히 0..3입니다.

로그는 원래 추정 주소에서 일치하지 않았다는 사실까지만 증명합니다. 실제 코드가 이동했는지,
패턴 자체가 다른지까지는 증명하지 않습니다. 새 검색이 일치하지 않으면 선택은 계속 거부되며
그 사유가 로그에 남습니다. 적용 함수의 비영(非零) 선택 경로도 여전히 실행 미검증입니다.

## UI

제공된 스크린샷의 첫 플레이어 카드 오른쪽에 세 개의 사각 버튼을 세로 배치합니다.
위에서부터 저장(디스크 아이콘), 불러오기(화살표 아이콘), 랜덤(주사위 아이콘)입니다.
저장·불러오기는 후속 기능 자리로 비활성화하며 호버 시 `추후 추가 예정`을 표시합니다.
장기 의도는 평소 장비를 빠른 복원 슬롯에 저장하고 랜덤 선택 후 바로 되돌리는 것입니다.
이번 버전에는 저장 파일이나 불러오기 동작을 만들지 않았습니다.

우측 상단 진단 패널은 제거했습니다. 버튼 옆 설명은 호버 또는 상태 변경 시에만 나타납니다.
1920×1080 기준 좌표를 화면에 맞게 비례 확대하고 중앙 정렬합니다.
이는 사진 기반 엔진 오버레이이며 정식 메뉴 위젯이나 네이티브 카드 위치 연결은 아닙니다.
다인원 배치·다른 화면비·컨트롤러 포커스·실제 글꼴 출력은 검증하지 않았습니다.
랜덤 기능의 현재 범위는 스트라타젬 4칸이며 다른 장비는 미완성입니다.

## 설치·제거와 수행 범위

설치 파일: `dist/RLMmods-0.1.4-private-untested.zip`.
게임을 닫고 기존 RLMmods를 모두 비활성화한 뒤 새 ZIP만 가져와 Deploy합니다.
Bingus는 있거나 없어도 시작하도록 기존 boot 경로를 유지합니다.
다른 boot.lua 교체 모드와는 충돌합니다. 제거는 같은 매니저에서 비활성화 후 Purge/Deploy합니다.

컴파일·패키징만 수행합니다. 게임 실행, 테스트, 모드 매니저 설치와 플레이 검증은 하지 않습니다.
자동 설치·원본 덮어쓰기·소스 ZIP 생성·원격 업로드는 하지 않습니다.
패치는 원본 boot 바이트코드를 포함하므로 공개 저장소에 올리지 않습니다.
