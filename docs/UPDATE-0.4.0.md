# 0.4.0: 버튼 이미지와 모드 아이콘

설치 파일: `dist/RLMmods-0.4.0-private-untested.zip`. 이전 RLMmods는 모두 끄고 교체하세요.
컴파일·패키징과 정적 확인만 했고, 게임과 모드 매니저에서는 확인하지 않았습니다.

## 버튼 이미지

| 버튼 | 원본 (수정하지 않음) | 원본 상태 |
| --- | --- | --- |
| 저장 (아래 화살표) | `docs/design/icons/512-v4/save-default.png` | 기본 |
| 불러오기 (위 화살표) | `docs/design/icons/512-v4/load-default.png` | 기본 |
| 랜덤 (주사위) | `docs/design/icons/512-v2/random-hover.png` | 호버 |

게임의 Lua GUI는 PNG를 직접 불러올 수 없습니다. 텍스처·머티리얼 리소스를 패치에 넣는 방식은
이 프로젝트에서 형식을 확인한 적이 없어 쓰지 않았습니다. 대신 `tools/make_ui_images.py`가
원본 PNG를 64×64·128×128로 줄인 픽셀 행 데이터 `src/ui_images.lua`를 만들고, `ui.lua`가
같은 색 픽셀 구간을 사각형으로 그립니다. 버튼이 80px 이하면 64, 크면 128 데이터를 씁니다.
버튼 이미지에 배경·테두리·모서리 표시가 모두 들어 있으므로 그 밖에는 아무것도 덧그리지 않습니다.

상태별 이미지는 원본의 도형을 유지한 색 변환입니다.

| 상태 | 색 |
| --- | --- |
| 기본 | 차콜 바탕, 흰 아이콘·테두리, 노란 모서리 |
| 호버·누름 | 노란 바탕, 어두운 아이콘·테두리·모서리 |
| 비활성 | 어두운 차콜 바탕, 회색 아이콘 |

랜덤 원본은 호버 상태이므로, 기본 상태는 같은 도형을 역변환해 만들고 모서리의 노란색은
저장 버튼의 모서리 위치에서 가져옵니다. 랜덤 버튼은 마우스를 올렸을 때만 호버로 표시합니다.
위치·크기·간격과 클릭 영역은 이전과 같습니다(1920×1080 기준 68px, 간격 12px, 화면 비율에 맞춰 조정).
불러오기는 저장 파일이 없으면 비활성이고 툴팁에 `저장된 구성 없음`을 표시합니다.
화면 상태 때문에 누를 수 없을 때는 세 버튼 모두 비활성이며 툴팁에 이유를 표시합니다.

이미지를 바꾸면 `python tools/make_ui_images.py`를 다시 실행한 뒤 빌드합니다.

## 모드 아이콘

`docs/design/rlmmods-mod-icon-512-v1.png`(겹친 주사위)를 설치 ZIP 최상위 `icon.png`로
바이트 그대로 복사하고, `manifest.json` 최상위 `"IconPath": "icon.png"`로 연결합니다.
HD2 모드 매니저 사용자 보고에 따르면 `IconPath`는 확장자까지 포함한 파일 이름이어야 합니다.
게임 안 버튼은 단일 주사위, 매니저 아이콘은 겹친 주사위입니다.

## 확인하지 않은 것

게임 안 표시(선명도, 위치, 사각형 개수에 따른 성능), 모드 매니저의 아이콘 표시, 설치·실행.

## 0.4.1 지원무기 1개 규칙

랜덤 스트라타젬 4칸에 지원무기도 최대 1개만 나옵니다(배낭 1개·차량 1개 규칙에 추가).
0.2.1 기록의 후보 91개를 비교한 결과, 플래그(`+0x104`)의 `0x1` 비트가 HD2Runtime 분류의
지원무기 33종에만 켜져 있고 나머지 58종에는 꺼져 있었습니다. 이 비트로 판별합니다.
배낭을 함께 메는 지원무기(오토캐논, 스피어 등)는 지원무기·배낭 두 규칙에 모두 해당합니다.
불러오기에는 랜덤 전용 규칙을 적용하지 않습니다. 로그 `Catalog:` 줄에 후보 중 지원무기 수가 남습니다.
