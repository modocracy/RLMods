# 0.1.7: 부스터 랜덤 선택

랜덤 버튼을 누르면 스트라타젬 4칸 뒤에 부스터 1개도 무작위로 고릅니다.
두 결과는 서로 독립적입니다. 부스터가 거부되어도 스트라타젬 결과는 유지됩니다.
컴파일·패키징만 했고, 게임 안 동작은 아직 확인하지 않았습니다.

설치 파일: `dist/RLMmods-0.1.7-private-untested.zip`. 이전 RLMmods는 모두 끄고 교체하세요.

## 근거 (사용자 실행 데이터)

0.1.6 진단판이 사용자 세션에서 기록한 내용입니다.

- 부스터 목록: 패널 포커스 4, 목록 종류(category) 5, 19행.
- 직접 고른 부스터는 내 로드아웃 블록 `+0x130`에 부스터 ID(u32)로 저장됨.
- 같은 세션에서 저장한 game.dll 실행 영역 사본을 Capstone 5.0.7로 해석함.
  사본은 사용자 PC의 `%LOCALAPPDATA%\RLMmods\`에만 있고 배포물에 넣지 않음.

해석한 게임 코드 (빌드 25480438, timestamp `0x6AB3B43F`):

| 위치 | 역할 |
| --- | --- |
| `0x146E0A0` | 목록 확정 처리. `[screen+0x2818]` 종류로 분기 (1/3/5/10) |
| `0x146E6DC` | 종류 5(부스터) 분기. 목록 선택값을 부스터 번호로 사용 |
| `0x875800` | 부스터 번호 장착. 내부에서 팀 중복 검사 후 호스트/클라이언트 동기화 |
| `0x875110` | 팀 중복 검사(읽기 전용). 0은 항상 허용, 21 이상 거부 |
| `0xBDE430` | 이벤트 `0x5D509124`(플레이어, 부스터 ID) 전송 |
| `0x1893D40` | 패널의 부스터 표시 갱신 |
| `0x32FDA90` | 부스터 표 21개, 간격 0x38, 첫 u32가 부스터 ID |
| `0x146EB49` | 목록 열기: 포커스 4이면 종류 5 |

## 구현 방식

1. 게임의 목록 열기 함수로 부스터 목록을 엽니다(스트라타젬과 같은 방식).
2. 목록이 선택 가능으로 표시한 행 중, 팀 중복 검사를 통과하고 현재 부스터가 아닌 것만 후보로 씁니다.
3. 게임의 확정 처리와 같은 함수·인자·순서로 장착, 이벤트 전송, 패널 갱신, 목록 닫기를 실행합니다.
4. 이후 몇 프레임 동안 로드아웃 블록 `+0x130`이 고른 ID로 바뀌는지 로그에 기록합니다.

의존하는 코드 구간 8곳의 바이트가 정확히 일치할 때만 활성화됩니다.
하나라도 다르면 부스터 기능만 꺼지고 스트라타젬 랜덤은 계속 동작합니다.
소유·해금 값이나 선택 제한을 직접 쓰지 않습니다.

## 확인하지 않은 것

게임 실행, 실제 부스터 변경 표시, 출격 후 적용, 멀티플레이에서 팀원 화면과 중복 제한.
0.1.6의 진단 기록(목록 변화 로그, 코드 사본 저장 1회)은 계속 남습니다.
