# 0.6: 배포용 빌드 (게임 코드 미포함)

설치 파일: `dist/RLMmods-0.6.3.zip`. 게임 실행 확인: 0.6.0, 0.6.2. 0.6.3은 미확인.

## 0.6.0 원본 boot 미포함

이 모드는 게임의 `boot.lua`를 교체합니다. 0.5.x까지는 원본 boot 바이트코드(326바이트)를 넣고 먼저 실행했습니다.
0.6.0부터 배포용 빌드는 원본을 넣지 않고, 원본이 하는 일을 직접 작성한 `STANDALONE_BOOT`
(`tools/build_patch.py`)를 씁니다.

원본 boot의 동작 (구조만 해석, 바이트는 복사하지 않음):

```lua
function init() require('core/wwise/lua/wwise_flow_callbacks') end
function shutdown() end
function update(dt) end
function render() end
if stingray.Application.build() ~= 'release' then require('debug') end
if rawget(_G, jit) then jit.off() end
```

`--original-resource`나 `--game-data`를 주면 예전처럼 원본을 넣은 개인용 빌드를 만듭니다.

## 0.6.1 코드 고정값을 지문으로

모드는 게임 함수를 부르거나 읽기 전에 그 위치의 기계어가 예상과 같은지 확인합니다.
0.6.0까지는 비교 기준으로 기계어 바이트(합계 약 4.2KB)를 16진수로 소스에 적어 두었습니다.
0.6.1부터는 그 자리를 `pin:<길이>:<제외 위치>:<지문>` 문자열로 바꾸었습니다.

- 지문: 해당 길이의 바이트에서 제외 위치(재배치 주소 등 `??`)를 뺀 FNV-1a 64비트 값.
- `platform.lua`의 `P.match`가 게임 메모리를 읽어 같은 방식으로 계산해 비교합니다.
  자주 다시 확인하는 곳(소유권 판정)은 처음 확인할 때 읽은 메모리 바이트와 비교합니다.
- 소유권 코드의 위치는 예전 검색 결과(`0x136F910`)로 고정하고 지문으로 확인합니다.
  지원 빌드가 하나뿐이므로 결과는 같습니다.
- 변환 도구: `python tools/hash_pins.py`(변환), `python tools/hash_pins.py --check`(남은 패턴 검사).

검증:

- 50개 지문 모두 저장해 둔 게임 코드 사본과 일치했고, 같은 Lua 코드를 게임의 LuaJIT 라이브러리로 실행해도
  50개 모두 일치·한 글자 바꾼 지문 0개 통과였습니다.
- 저장소의 모든 텍스트 파일에서 게임 기계어와 같은 8바이트 이상 16진수 조각: 0개.
- 64비트 숫자 상수는 실행 중에 만듭니다. 상수로 쓰면 컴파일 결과가 FFI 전용 형식이 되어 빌드 검사에서 거부됩니다.

게임 업데이트로 주소가 바뀌면, 새 빌드의 코드 사본에서 바이트를 확인해 새 지문을 만들어야 합니다.

## 0.6.2 개수·용량 값을 게임 코드에서 읽기

새 부스터·장비·스트라타젬이 늘어도 모드가 정한 숫자 때문에 막히지 않도록, 고정 숫자였던 값을
게임 코드의 명령어 피연산자에서 읽고 서로 대조합니다. 게임 업데이트 전체를 자동 지원한다는 뜻은 아닙니다.
빌드가 바뀌면 timestamp 검사와 지문 검사로 모드는 계속 꺼집니다.

### 바뀐 값

| 값 | 0.6.1 | 0.6.2 근거 (지원 빌드 결과) |
| --- | --- | --- |
| 부스터 표 위치·행 수·행 크기 | `0x32FDA90`, 21, `0x38` 고정 | 장착 처리 `0x146E6DC`(행 수 imm32 +7, 경계 imm8 +26, 크기 +34, 표 RIP +38), 팀 중복 검사 `0x875110`(경계 +46), 패널 표시 `0x1893D40`(표 RIP +37, 크기 +57, 경계 +60) 세 곳 일치 → `0x32FDA90`, 21, `0x38` |
| 선택 목록 용량 | 256 고정 (스트라타젬·장비) | 목록 행 추가 `0x18D442D`: 선택 가능 배열 `+0x92DC2` 다음 배열이 `+0x92EC2` → 256행. 행 수·ID·선택 가능 위치가 기존 목록 필드와 일치해야 함 |
| 진행도(소유) 표 용량 | 4096 고정 (소유권·장비) | 소유 판정 `0x136F910`의 피연산자(개수 `+0x1CE0`, 행 `+0xB9CE4`, 행 크기 `0x18`, 상태 크기 `0xB8`, 상태값 `+0x1CF8`)와 장비 표시 `0x18975D0`의 다음 표 시작 `+0xD1CE4`. 상태 배열 `(0xB9CE4-0x1CE4)/0xB8`와 행 배열 `(0xD1CE4-0xB9CE4)/0x18`이 모두 4096이어야 함 |
| 스트라타젬 offer 범위 | `last-first<=512`, `count<=65536` (근거 없음) | `last`·`count` 모두 진행도 표 용량 이하 |

부스터 목록 행 수는 표 크기 대신 쓰지 않습니다. 목록은 소유·임무·팀 상태에 따라 일부만 보여 줍니다.
부스터 경계값은 부호 있는 8비트 비교 피연산자이므로 128행 이상이면 다른 코드가 필요하고, 그 경우 지문이 달라져 기능이 꺼집니다.
대조가 하나라도 어긋나면 해당 기능(부스터·스트라타젬·장비)만 꺼지고 로그에 이유가 남습니다.
시작 로그에 `Booster table from code`, `List capacity from code`, `Progression capacity from code` 줄이 남습니다.

### 유지한 제한과 이유

| 제한 | 성격 |
| --- | --- |
| 부스터 0번(미선택) 제외 | 팀 중복 검사가 0번만 항상 허용하는 코드(지문 고정)에 근거 |
| 스트라타젬 종류 수 `L.types` | 이미 명령어(`kind_frv`)에서 읽는 값. `<4096`은 읽은 값의 이상 여부만 보는 방어용 검사 |
| 슬롯 간격·화면 오프셋 범위 (`slot_stride`, `slot`, `local_index`) | 명령어에서 읽은 값의 방어용 범위 검사 |
| 메모리 읽기 크기(소유권 4KB 단위, 플랫폼 1MB), 주소 범위 | 읽기 안전 장치. 게임 구조와 무관 |
| 로컬 플레이어 번호 0~3, 슬롯 4칸 | 화면 구조(패널 4개, 스트라타젬 4칸) 고정값. 지문으로 보호되는 코드에서 확인 |
| 배낭·차량·지원무기 분류 | 플래그 비트가 기준이라 새 스트라타젬도 자동 분류. ID 목록(`stratagem_rules.lua`)은 예비용 |

### 확인하지 않은 것

게임 실행. 값 대조는 저장해 둔 game.dll 코드 사본으로 했고, 지문 대조 코드는 게임의 LuaJIT 라이브러리로 실행해 52개 모두 일치를 확인했습니다.

## 0.6.3 프레임 부담 줄이기와 코드 정리

기능은 그대로 두고, 버튼이 보이는 동안 매 프레임 하던 일을 줄였습니다.

| 매 프레임 하던 일 | 0.6.3 |
| --- | --- |
| 메모리 숫자 읽기마다 문자열 생성 (약 20회) | 재사용 버퍼에 직접 읽음. 문자열 생성 없음 |
| 게임 `update` 결과를 테이블에 담았다 풀기 | 테이블 없이 그대로 넘김(빈 값 포함 개수 보존) |
| 키 입력 검사: 메모리 5회 이상 읽기 | 대기 중에는 ↑ 키 표시만 확인, 눌렸을 때만 나머지 확인 |
| 장비 상태 점검(메모리 약 12회 읽기) | 6프레임마다, 그리고 저장·불러오기·랜덤 직후 바로 |
| 창 포커스·크기 확인(윈도우 API 3회) | 30프레임마다. 커서 위치는 매 프레임 |
| 오버레이 화면 목록 조회 | 30프레임마다 |
| 다시 그릴지 판단용 문자열 생성 | 값 비교로 판단. 변화 없으면 아무것도 만들지 않음 |
| 키 입력용 함수·테이블 생성 | 미리 만든 함수·테이블 재사용 |

정리한 코드:

- 무기 3종 위치를 장착할 때마다 로드아웃 기록 전체(약 2.5KB)에서 찾던 반복을 없앴습니다. 대신 게임의 장비
  표시 갱신 함수 `0x18991A0`이 쓰는 6칸 정보(기록 위치·표시 칸·종류)를 읽어 `SLOTS`와 대조합니다.
- 쓰지 않던 코드 제거: 전체 랜덤 계획 함수와 분류 목록(randomizer), 0.2.1 조사용 스트라타젬 행 기록,
  스트라타젬 외 소유권 판정 경로와 미사용 함수(ownership), 미사용 상태 필드(bootstrap, stratagems, ui).

검증: 컴파일·패키징, 지문 52개 대조(코드 사본·게임 LuaJIT 모두 일치), 새 메모리 읽기 함수와 `update` 전달을
게임 LuaJIT으로 실행해 확인, 장비 6칸 정보를 코드 사본과 대조. 게임 실행은 하지 않았습니다.
